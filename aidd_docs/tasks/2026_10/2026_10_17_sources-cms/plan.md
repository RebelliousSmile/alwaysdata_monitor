### Dépendances

- **F1 (#15)**, utilisé tel quel : `Draft` et `Advisory::build(Draft)` (seule porte d'entrée), `provided_score`, `attribution` (2 000 caractères), `informational`, `Scheme::Php` (sémantique `version_compare`, versions à quatre composants), `Bound::{Floor, At}`, événements `introduced` / `fixed` / `last_affected` évalués par le pseudo-code OSV (mélange compris), lignes `unevaluable` → `Unknown(RangeUnknown)`, `Tally` par raison, `vulns/purl.rs`, `Load` par générations, CLI `vigie vulns sources | show | match`. F1 prévoit déjà que la table des corrections de plage est clé `(source, advisory_id, purl)` et hors des générations : F3 la crée.
  F1 porte une **borne unique de 256 plages par ligne** `affected` (au-delà, ligne `unevaluable`, jamais écartée) : elle suffit aux failles du noyau WordPress (une plage par branche) ; F3 n'ajoute aucune borne par source.
- **F2 (#16)**, plan `aidd_docs/tasks/2026_10/2026_10_17_synchro-failles/plan.md` (écrit en parallèle, relu le 2026-10-17 ; à relire avant la phase 3, tout écart est reporté ici). F3 s'appuie sur :
  - le trait `VulnSource` (`vulns/sync/mod.rs`) : `id()`, `meta() -> SourceMeta` (URL, licence, attribution, hôtes, plafonds), `ready(&SyncContext) -> Result<(), NotReady>` (par défaut `Ok`, F3 l'implémente pour Wordfence), `fetch(&mut Download, &mut dyn Sink, &mut Tally) -> Result<FetchOutcome, SyncError>`, `FetchOutcome { Unchanged, Loaded }`, poussée **en flux** par lots dans `Load` (pas de `Vec<Advisory>`) ;
  - `Download` (`vulns/sync/download.rs`) : HTTPS, hôtes codés en dur par source (redirections comprises, 3 au plus), en-têtes sensibles (`Authorization`) retirés dès qu'une redirection change d'hôte et jamais journalisés, `If-None-Match` / `If-Modified-Since`, 304 → `NotModified`, corps écrit en flux dans `<dossier de la base>/vulns-work/<source>/` (0700, fichier 0600) avec SHA-256, `Content-Length` contrôlé, échéance par source ; jamais de `Content-Encoding` demandé ;
  - le moteur : bail pris **avant** le téléchargement, empreinte identique → aucune génération, garde de rétrécissement (moins de 80 % de l'active → `refused_shrink`, `--accept-shrink`), échec → base précédente intacte, `last_attempt_at`, `last_outcome`, `last_error` dans `vuln_sources` ;
  - le **débit par source** (F2) : intervalle minimal entre deux requêtes déclaré dans `SourceMeta`, colonnes `last_request_at` et `retry_after_until` de `vuln_sources`, `SyncError::Status` (code HTTP, `Retry-After` lu et borné) ; F3 **déclare** ses valeurs et ne réimplémente rien ;
  - le **seuil générique `max_dropped_ratio`** (F2), déclaré par source dans `SourceMeta` et appliqué **avant** la garde de rétrécissement ;
  - la configuration `[vulns] sources = [...]`, liste fermée (F3 y ajoute `wordfence` et `friends-of-presta`), et ses sous-sections par source ;
  - le constat `vulns-sync/<source>` du pseudo-site réservé `_veilleur` (`WATCHER_SITE`), ouvert par `tick` au-delà de 3 jours sans succès ;
  - `SyncOptions { trust, endpoint_override, limits_override }`, construit par le code seulement, et le serveur HTTPS de test `tests/support/dump_server.rs` ;
  - `flate2` promu en dépendance par F2 ; F2 n'écrit **ni lecteur tar ni lecteur YAML** : le lecteur tar est à F3 (`vulns/sources/tar.rs`, phase 2).
- **F2 tel qu'implémenté (relu avant la phase 3, écarts reportés)** : `SourceMeta.loader_version` existait déjà (F3 n'ajoute que `redistribution`) ; la colonne `vuln_sources.revision` existait (0017) sans écrivain : F3 ajoute `Dumped.revision` et `SyncMeta.revision`, écrits avec la bascule, et `SyncState.revision` ; `registry::build(id)` ne reçoit pas la configuration : F3 ajoute `registry::build_with(config, id)` (Wordfence et sa section), appelé par `sync::run` ; `NotReady` est une chaîne (pas d'énumération) ; `Request.sensitive_headers` passe de `String` à `HeaderValue` (valeur marquée sensible) ; F3 ajoute `SyncError::Format` (flux ou archive illisible) et `SyncError::NotReady` (verrou revérifié par `fetch`), et les messages 401/403 disent « jeton refusé » ; le débit réserve la fenêtre avant `fetch`, si bien qu'un refus de `fetch` consomme la fenêtre de 30 min (aucune requête ne part).

### Décisions F0 appliquées ici (résumé ; `decisions.md` fait foi)

- Wordfence **v3**, flux `production` (porte `cve` pour KEV et EPSS, `cvss` pour la gravité) ; jeton gratuit dans un fichier 0600 sur le VPS ; une requête toutes les 30 minutes au plus, synchronisation quotidienne ; **admis sous réserve** : import non branché avant la relecture consignée et datée ; usage **interne à l'exploitant** ; `copyrights` reproduit partout où la faille est affichée, avec le lien `https://www.wordfence.com/threat-intel/vulnerabilities/id/<id>`.
- Friends-Of-Presta : Markdown à en-tête YAML, `Impacted release` en texte libre, analyse prudente ; formulation non reconnue → « plage inconnue », signalée pour toute version du module ; **correction de plage** auditée, distincte d'une dérogation ; CC BY-SA 4.0, usage interne affiché avec attribution, un document client ne reprend que des faits (CVE, module, plage, vecteur CVSS, CWE, date) et le lien ; catégorie `dependancies` écartée et comptée `out_of_scope`.
- purl : `pkg:wordpress/plugin/<slug>`, `pkg:wordpress/theme/<slug>`, `pkg:wordpress/core/core`, `pkg:prestashop/module/<nom_technique>`, `pkg:prestashop/core/prestashop`, grammaire commune de `failles.md`. **Écarts à l'issue #17**, qui proposait `pkg:wordpress-plugin/…`, `pkg:prestashop-module/…` et, dans son commentaire, `pkg:wordpress/core/wordpress` : `failles.md` fait foi (`core/core`).
- Gravité : `cvss.score` Wordfence, puis score de la ligne `severity` de Friends-Of-Presta ; `informational: true` porté par le modèle.
- Fixtures Wordfence et Friends-Of-Presta **toujours fictives**, de même structure ; `example.org` seulement.
- Hôtes depuis le VPS : `www.wordfence.com` ; `github.com` et `codeload.github.com`.

## Decisions

| Decision | Why |
| -------- | --- |
| **Verrou de relecture à deux clés.** (1) Constante du binaire `WORDFENCE_TERMS_REVIEWED: Option<&str>` (`vulns/sources/wordfence.rs`), `None` jusqu'au commit qui consigne la relecture dans `failles.md` ; un test lit `failles.md` et exige que la ligne « Relecture des conditions depuis le VPS » et la constante disent la même chose (`non faite` ↔ `None`, `faite le AAAA-MM-JJ` ↔ `Some("AAAA-MM-JJ")`). (2) Configuration `[vulns.wordfence] terms_reviewed = "AAAA-MM-JJ"`, obligatoire, égale à la constante ; `wordfence` dans `[vulns] sources` exige la sous-section et réciproquement (sinon `ConfigError`, règle F2 des identifiants). Sans déclaration : source absente. Section présente mais constante `None` ou dates différentes : **refus explicite** de la source à chaque synchronisation (« source wordfence désactivée : relecture des conditions non consignée dans docs/failles.md »), sans aucune requête, visible dans `vulns sources` ; `fetch()` **revérifie** la constante et la date juste avant la requête (un appel direct de `fetch` sans `ready` ne contourne pas le verrou) ; au-delà de 3 jours, le constat `vulns-sync/wordfence` de F2 s'ouvre ; la configuration reste **valide** (ni `serve` ni `tick` ne s'arrêtent) | La réserve de F0 tient au code, pas à la mémoire : un exploitant ne peut pas activer seul la source avant que la relecture soit publiée dans le dépôt, et une relecture consignée n'active rien sans geste explicite sur le VPS. Une configuration refusée arrêterait tout le veilleur (incident du 2026-10-16 : section inconnue refusée) |
| **Pas d'expiration de la relecture** | Les conditions sont « *perpetual … irrevocable* » [S] ; une relecture à refaire chaque année ferait périmer la base sans raison. Une nouvelle relecture se consigne en changeant constante, `failles.md` et configuration |
| **Usage interne porté par la source** : `Redistribution { Internal, FactsOnly, Free }` : **F3 ajoute ce champ à `SourceMeta` de F2** (qui ne l'a pas) et le renseigne pour les sources OSV de F2 ; la fonction qui le donne pour un identifiant est **`vulns::sync::registry::redistribution(source_id: &str) -> Option<Redistribution>`**, un `match` avec un bras explicite par source de `registry::KNOWN`, F4 comprises (`wordfence` → `Internal`, `friends-of-presta` → `FactsOnly`, `osv-crates-io`, `osv-packagist`, `osv-npm`, `kev`, `epss` → `Free`), le seul bras final `_ => None` couvrant un identifiant inconnu (F7 le traite comme `Internal`, fail-closed) ; un test exige `Some` pour chaque identifiant de `KNOWN` : une source ajoutée sans niveau fait échouer ce test, et ne compile pas sans le champ `redistribution` de `SourceMeta` ; imprimé par `vigie vulns sources` et `show`, lu par F7 ; une faille fusionnée par CVE (F7) prend le niveau **le plus restrictif** de ses sources | F7 (API, rapports) a une seule question à poser avant de transmettre une faille, et un identifiant lu en base mais inconnu du binaire ne doit jamais valoir `Free` par défaut ; une constante du code ne dérive pas comme une colonne ; une fusion ne doit pas faire sortir un fait Wordfence par une GHSA homonyme |
| **Jeton : `secret.rs` extrait de `command/key.rs`** (`open_safely`, `check_parent`, `check_mode` déplacés sans changement de règle : fichier 0600, dossier 0700, propriétaire = uid du veilleur, `O_NOFOLLOW`, vérification sur le fichier ouvert) ; `key.rs` s'en sert ; `read_token(path)` : `symlink_metadata` avant l'ouverture (fichier ordinaire exigé : une FIFO ou un périphérique est refusé sans bloquer) et ouverture en `O_NONBLOCK` en plus, lecture bornée (`take(1 Kio)`), `\r` et `\n` finaux retirés, puis `[A-Za-z0-9._~+/=-]{16,512}`, sinon refus ; type `Token` sans `Debug` ni `Display` en clair (`Token(***)`) ; l'en-tête est construit en `HeaderValue` marquée sensible (`set_sensitive(true)`) ; lu à chaque synchronisation, jamais copié en base ni en journal. `alert.rs` n'est pas touché | Une seule règle de droits pour les secrets lus par le code (inventaire « Secrets » de `hebergement.md`) ; un fichier remplacé par une FIFO ou gonflé ne bloque ni n'épuise le veilleur ; la grammaire empêche une injection d'en-tête ; un jeton ne doit pas fuir par un `{:?}` ni par une trace HTTP |
| **En-tête `Authorization: Bearer <jeton>`** en dur [NV], confirmé ou corrigé par la relecture depuis le VPS (phase 4) ; hôtes Wordfence réduits à `www.wordfence.com` : toute redirection vers un autre hôte est refusée par `Download` (F2), qui retire aussi l'en-tête dès que l'hôte change ; 401 et 403 → « jeton refusé », sans texte de la réponse | La forme exacte n'est vérifiable que depuis le VPS ; la liste d'un seul hôte garantit que le jeton ne part vers aucun autre |
| **Débit Wordfence, par le mécanisme de F2** : `SourceMeta` déclare un intervalle minimal de 30 min ; F2 refuse la requête avant l'échéance (`last_request_at`, écrit avant la requête), garde `retry_after_until` sur un 429 (`SyncError::Status`, `Retry-After` borné) et l'impose à la tentative suivante ; F3 n'ajoute aucune colonne ni aucun compteur | La limite de Wordfence est par requête, réussie ou non ; un `vigie vulns sync` lancé à la main juste après le timer ne doit pas la dépasser ; un seul mécanisme de débit pour toutes les sources |
| **Flux `production`** | `cve` (jonction KEV, EPSS, fusion GHSA) et `cvss` (gravité) n'existent pas dans `scanner` |
| **Lecture du flux Wordfence en flux** : corps écrit par `Download` dans le dossier de travail (plafond 512 Mio), relu par `serde_json::Deserializer::from_reader(Compteur(BufReader(File)))` ; le compteur d'octets est la couche **externe**, partagé par `Rc<Cell<u64>>` et remis à zéro par le `Visitor` avant chaque `next_key` ; chaque valeur est lue en `Box<RawValue>` (fonctionnalité `raw_value` de `serde_json`), puis `serde_json::from_str::<WfRecord>(raw.get())`. **Seuls `id` et `software[].type` / `slug` sont stricts** : une forme inattendue de ces champs écarte la faille (`bad_record`) ; tout autre champ (`title`, `cve`, `cvss`, `cwe`, `references`, `copyrights`, `patched`, `patched_versions`, `affected_versions`, `informational`, dates…) est lu en `Option<Box<RawValue>>` puis décodé à part : `null`, `[]` et `{}` valent « vide » (le `json_encode` de PHP écrit un tableau associatif vide en `[]`), un échec retire **ce seul champ** avec sa raison F1 (`bad_severity`, `bad_reference`, `bad_published`, `empty_copyrights`…) ; `bad_date` est réservé à la faille écartée faute de `modified` après tous les replis (Wordfence : `updated` puis `published` ; FOP : `Published at` puis date du nom de fichier), et `affected_versions` vide ou illisible rend la ligne `unevaluable` : la faille n'est jamais écartée pour un champ secondaire ; une erreur de syntaxe JSON ou une valeur de plus de 4 Mio (compteur) est une **erreur de flux** (chargement abandonné) ; chaque faille est convertie puis poussée par lots | ≈ 123 Mo de JSON brut [S] : ni l'arbre entier ni le corps en mémoire, la mémoire reste bornée par une valeur et un lot, sous le `MemoryMax` de l'unité F2 ; séparer syntaxe (flux), identité (faille) et champs secondaires (champ seul) garde une anomalie au plus petit périmètre possible sans masquer un flux corrompu ; une faille d'un paquet identifié ne disparaît pas pour un CWE mal formé (règle F1) |
| **Conversion Wordfence** : id `WF-<uuid>` (UUID validé puis mis en minuscules ; clé de l'objet et `id` comparées après cette normalisation, différentes → `bad_id`) ; `aliases` = `cve` ; un `software[]` → une ligne `Affected` (`plugin` → `pkg:wordpress/plugin/<slug>`, `theme` → `pkg:wordpress/theme/<slug>`, `core` → `pkg:wordpress/core/core`, autre type → `out_of_scope`, slug hors grammaire → `bad_purl`), `scheme` PHP ; un libellé d'`affected_versions` → une plage `ECOSYSTEM` : `from_version` `*` → `Bound::Floor`, sinon `introduced` (inclusive même si `from_inclusive: false`, limite F1) ; `to_version` `*` → plage ouverte ; `to_inclusive: true` → `last_affected`, `false` → `fixed` ; borne illisible ou `from` > `to` → ligne `unevaluable` | Les bornes Wordfence se traduisent sans perte en événements OSV, sauf la borne basse exclusive, traduite du côté prudent (signalement de trop) |
| **Version corrigée Wordfence** : si `patched: true`, le plus petit `patched_versions[]` strictement supérieur à `to_version` (comparateur PHP) est ajouté en `fixed` à la plage close par `last_affected` ; `patched: false` → aucun `fixed`, « aucun correctif » affiché par F7 | Sans cela, une plage `last_affected` n'aurait pas de version corrigée et F7 dirait « aucun correctif » à tort ; le mélange `last_affected` puis `fixed` est évalué par le pseudo-code OSV de F1 sans changer le verdict |
| **Champs Wordfence gardés** : `title` → `summary` ; `cvss.score` lu **comme texte** depuis son `RawValue` (nombre JSON `\d{1,2}(\.\d)?`), converti en dixièmes exacts → `Score { tenths: u8 (0..=100), origin: wordfence }` de F1 (`6.1` → 61) ; plus de 100 dixièmes, plus d'une décimale, exposant ou autre forme → `bad_severity`, champ retiré seul ; jamais `(f * 10.0) as u8`, `cvss.vector` → `severity` ; `cwe.id` → `CWE-<id>` ; `references[]` (type `WEB`) ; `informational` ; `published` → `published`, `updated` (sinon `published`) → `modified`, au format RFC 3339 ou `AAAA-MM-JJ hh:mm:ss` lu en UTC [NV] ; `source_url` = lien de l'enregistrement. `description`, `remediation`, `researchers` ne sont pas stockés | Même règle que F1 (`details` jamais stocké) ; seuls les faits utiles au rapprochement et à l'affichage |
| **Attribution Wordfence** : `copyrights.message`, puis les autres clés **triées**, chacune `notice`, `license`, `license_url`, assemblées en texte et assainies, plus le lien de l'enregistrement ; `license_url` est gardée en texte, **jamais en lien actif** ; `copyrights` présent mais vide (`{}`, forme admise par la source) : mention fixe « Wordfence Intelligence, © Defiant Inc. — <lien> », compté `empty_copyrights` (information, hors `max_dropped_ratio`) ; `copyrights` absent ou au-delà de 2 000 caractères : faille **gardée**, même mention fixe, comptée `no_copyrights` ou `attribution_overflow` ; la synchronisation réelle mesure la longueur maximale avant l'activation | Un ordre trié rend l'attribution stable d'une synchronisation à l'autre ; une URL tierce ne devient pas un lien cliquable dans la console ; une mention tronquée ne respecterait plus la licence ; une faille écartée pour une raison administrative serait un faux négatif silencieux (règle F1) |
| **Archive Friends-Of-Presta** `https://github.com/friends-of-presta/security-advisories/archive/refs/heads/main.tar.gz` (redirection vers `codeload.github.com`, les deux hôtes autorisés) ; lecteur tar maison borné, à F3 puisque F2 n'en écrit pas : ustar ; en-têtes pax (64 Kio au plus ; enregistrement de longueur 0 ou débordant refusé ; clé `size` refusée) et GNU `L` lus pour le nom seulement ; tailles en base 256 refusées ; données des membres sautés et bourrage comptés dans le plafond décompressé ; `GzDecoder` mono-membre (un second membre gzip est une erreur) ; racine unique exigée ; seuls les fichiers ordinaires `<racine>/_posts/*.md` sont lus, chemins absolus, `..`, liens et périphériques ignorés et comptés ; commentaire pax global (empreinte du commit) gardé comme révision | Une archive par jour, sans clone git ; le format tar est court à lire et une crate `tar` ajouterait une surface pour peu ; le commit rend la synchronisation traçable |
| **En-tête YAML lu par un analyseur ligne à ligne fermé**, pas une crate YAML : clés `title`, `categories`, `severity` (les autres ignorées), scalaires nus ou entre guillemets, `categories` en scalaire, liste `[a, b]` ou puces `- a` ; en-tête de 64 lignes et 8 Kio au plus ; tout le reste (ancres, alias, blocs multilignes sur ces clés) → `bad_front_matter` | Aucun YAML général à analyser ; pas d'ancre ni d'alias récursif possible ; pas de nouvelle dépendance |
| **Corps** : section `## Summary`, puces `*` ou `-` de la forme `**Clé**: valeur` (clés comparées sans casse) : `CVE ID` (tous les `CVE-\d{4}-\d{4,}`, 32 au plus), `Published at` (`AAAA-MM-JJ`), `Product`, `Impacted release`, `Weakness` (`CWE-\d+`), `Severity` (repli du score) ; la ligne `**Vector string**` est cherchée dans tout le corps ; liens Markdown réduits à leur texte. Fichier de 1 Mio au plus (`too_large`) | Format observé sur un vrai avis [V] (`2023-09-21-cookiebanner.md`, relu sur raw.githubusercontent.com pour la conception, jamais copié en fixture) |
