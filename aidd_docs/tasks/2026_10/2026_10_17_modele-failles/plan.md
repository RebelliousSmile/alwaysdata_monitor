### Décisions F0 appliquées ici (résumé ; `decisions.md` fait foi)

- Schéma **OSV 1.9.x**, champs inconnus ignorés, champs retenus validés et bornés ; `withdrawn` ignorées ; plages `ECOSYSTEM` et `SEMVER` traitées, `GIT` ignorées ; `last_known_affected_version_range` lu.
- Comparateur choisi selon **l'écosystème de la source** : Composer selon `composer/semver` (normalisation `VersionParser` puis `version_compare`), npm et Cargo selon semver, WordPress et PrestaShop selon `version_compare`. Plages toujours évaluées, `versions[]` en contrôle croisé. Version illisible : « version inconnue » ; plage illisible : « plage inconnue ».
- purl : grammaire commune de `failles.md` (slug WordPress `[A-Za-z0-9._-]{1,200}` tel quel, module PrestaShop `[A-Za-z0-9_-]{1,64}` tel quel, Composer `vendor/nom` ≤ 214 en minuscules, npm et cargo selon leurs définitions et tels quels, version `[0-9A-Za-z.+_-]{1,128}`). `vigie/src/vulns/purl.rs` est **le** module unique, importé par F5 (#19) ; ses vecteurs sont rejoués par le test PHP de l'agent.
- Correspondance Packagist : `prestashop/prestashop` → `pkg:prestashop/core/prestashop` ; `prestashop/<x>` (x ≠ `prestashop`) → **deux** purl, `pkg:composer/prestashop/<x>` et `pkg:prestashop/module/<x>` ; `wpackagist-plugin|theme/<slug>` → `pkg:wordpress/plugin|theme/<slug>` ; noyau WordPress `pkg:wordpress/core/core`.
- Score : `cvss.score` Wordfence > score `severity` Friends-Of-Presta > CVSS v3.1 calculé depuis le vecteur OSV > `database_specific.severity` GHSA (90, 70, 50, 30 dixièmes) ; jamais de calcul v4 ; `MAL-` repérées ; Wordfence `informational: true` porté par le modèle (une faille sans score reste alors information en F7).
- Licence par enregistrement (GHSA et EEF CC-BY 4.0, DRUPAL MIT, MAL Apache-2.0, RUSTSEC CC0) ; attribution Wordfence `copyrights` reproduite partout où la faille est affichée.
- Fixtures : OSV/GHSA réels seulement avec `NOTICE` ; Wordfence et Friends-Of-Presta toujours fictifs.

## Decisions

| Decision | Why |
| -------- | --- |
| **Aucune dépendance ajoutée.** Comparateurs, purl et CVSS v3.1 écrits ici ; dates RFC 3339 par `jiff`, URL par `url`, JSON par `serde_json` (champs ignorés par `IgnoredAny`, sans copie) | Le rapprochement est le cœur de la fiabilité : il doit être lisible et testé ici. Aucune crate ne reproduit `version_compare` ni `VersionParser::normalize`. Pas de nouvelle surface pour F8 ni pour musl |
| **Comparateur semver maison, pas la crate `semver`**, partagé par npm, Cargo et toute plage `SEMVER` : semver 2.0 strict (pas de zéro initial, pas de `v`, `=` ni forme partielle) ; noyau numérique de 18 chiffres au plus (sinon `Unparsable`) ; identifiants numériques de préversion comparés par **(longueur, ordre lexical)**, sans conversion ; préversions selon la §11 ; build validé puis **ignoré** dans l'ordre et l'égalité | Les événements OSV et les versions d'inventaire sont des versions exactes : seul l'ordre compte. `semver::Version` départage par le build, ce que semver 2.0 exclut. La comparaison par longueur évite tout débordement |
| **`php.rs` en deux étapes séparées.** (1) Canonisation exacte de `php_canonicalize_version` (`ext/standard/versioning.c`) : `-`, `_`, `+` et tout caractère non alphanumérique deviennent `.`, un `.` est inséré à chaque transition chiffre ↔ non-chiffre, jamais deux `.` de suite. (2) Comparaison sur **jetons classés** : numérique (18 chiffres au plus) ou mot spécial avec son rang `dev < alpha = a < beta = b < RC = rc < # < pl = p`, un composant restant comparé à `#` (`5.9 < 5.9.0`, `1.0-beta < 1.0 < 1.0pl1`) | WordPress et PrestaShop comparent ainsi. Séparer les étapes permet à Composer d'injecter ses propres jetons dans la même comparaison |
| **Domaine accepté de `version_compare`** : PHP apparie les mots inconnus par préfixe (`bogus` vaut `b`) et n'est pas transitif sur eux ; côté WordPress et PrestaShop, seuls les mots exacts ci-dessus, **sensibles à la casse comme PHP** (`RC` et `rc` seuls admis en deux casses), sont acceptés ; tout autre mot rend `Unparsable` | Ordre total (transitif, antisymétrique) sur le domaine accepté ; hors domaine, « version inconnue » plutôt qu'un verdict faux. Le test différentiel exige l'égalité avec PHP sur ce domaine |
| **Composer = `VersionParser::normalize` de `composer/semver`, puis la comparaison sur jetons de `php.rs`** : `+build` retiré ; `v` initial retiré ; majeur de 5 chiffres au plus (sinon versions-dates) ; complété à quatre composants (`1.2` → `1.2.0.0`) ; versions-dates `AAAA[.MM…]` (tout non-chiffre → `.`) ; suffixes **insensibles à la casse** (`ALPHA`, `Rc`) et canonisés comme `expandStability` : `a`/`alpha` → `alpha`, `b`/`beta` → `beta`, `rc` → `RC`, `p`/`pl`/`patch` → `patch`, `-stable` retiré, numéro accolé (`beta.2` → `beta2`), `-dev` final. Composer injecte `patch` au rang `pl` (PHP l'apparie à `p` par préfixe). `dev-*`, `*.x-dev` et alias de branche : `Unparsable`. Le résultat de normalisation est exposé (`normalize`) pour les vecteurs | Décision F0 (« Composer selon composer/semver ») ; c'est ce que fait Composer (`Comparator` sur versions normalisées). Seul Composer ignore la casse : PHP ne le fait pas |
| **Plancher OSV** : `introduced: "0"` est une borne **plancher** du modèle (`Bound::Floor`), jamais `parse("0")` | `"0"` n'est pas une version de chaque schéma (en semver, `0` n'est pas valide) ; il signifie « depuis toujours » |
| **Verdict à trois états** `Affected`, `NotAffected`, `Unknown(reason)` avec `reason ∈ { VersionUnknown, RangeUnknown }` ; `VersionUnknown` : version d'inventaire absente ou illisible ; `RangeUnknown` : plage ou borne illisible | F7 en fait « version inconnue » ou « plage inconnue » (information), jamais un silence (F0) |
| **Agrégation par faille** pour un purl : `Affected` si l'un de ses `affected` (lignes) l'est ; sinon `Unknown` si l'un l'est (raison de la première, `RangeUnknown` avant `VersionUnknown` à égalité d'ordre de lecture) ; sinon `NotAffected`. `fixed` le plus proche : le plus petit `fixed` supérieur à la version parmi les `affected` qui la contiennent. `divergence` calculée sur l'**union** des `versions[]` des `affected` du purl | Une GHSA peut porter plusieurs `affected` pour un même paquet (une plage par branche) : le verdict doit être celui de la faille, pas de la première ligne lue |
| **Aucune suppression silencieuse d'un paquet identifié.** Écart compté (faille entière) : entrée trop grosse, id invalide, `modified` absent ou non RFC 3339, id en double dans un même chargement (la seconde), aucun `affected` retenu. Écart compté (un `affected`) : paquet non identifiable (nom hors grammaire), écosystème hors périmètre. **Gardé et marqué `unevaluable`** (verdict `RangeUnknown`) : paquet identifié dont une plage est malformée (événement à zéro ou plusieurs clés, borne vide, hors grammaire ou illisible pour le comparateur, plus de 128 événements, plus de 256 plages dans la ligne : au-delà → `unevaluable`, jamais un écart). **Gardé, licence inconnue** : préfixe absent de `licence_for_id` (licence « inconnue », compté `unknown_license`, visible dans `vulns sources` et `show`). **Ignoré seul** : une entrée de `versions[]` hors borne (la plage reste) ; une référence refusée ; une gravité invalide. Un mélange `fixed`/`last_affected` dans une plage est **évalué** par le pseudo-code OSV, pas écarté | Une donnée cassée ne casse pas la synchronisation ; une faille d'un paquet identifié reste visible, au pire en « plage inconnue » ; les compteurs gardent l'anomalie visible |
| **GHSA multi-écosystèmes** : seuls les `affected` de l'écosystème du dump sont gardés (`Packagist` exact, `npm`, `crates.io`) ; `Packagist:https://packages.drupal.org/8` et les autres dépôts suffixés sont hors périmètre, comptés `out_of_scope` | Mesure : 638 `affected` Drupal et des centaines d'autres écosystèmes dans les dumps ; chaque faille est importée par le dump de son écosystème, sans doublon. Drupal n'est pas une typologie de Vigie (limite écrite) |
| **Évaluation** : pseudo-code « Evaluation » de la spécification OSV recopié en commentaire et couvert par vecteurs (événements triés, `introduced`/`fixed`/`last_affected`, `limit`) ; `fixed` sans `introduced` : plancher ajouté. `versions[]` : une version listée hors plages reste `Affected` (union d'OSV), drapeau `divergence` ; sans plage retenue, `versions[]` seule. Appartenance par égalité du comparateur | Décision F0 « plages toujours évaluées, `versions[]` en contrôle croisé » ; l'union est la lecture prudente |
| **Comparateur selon l'écosystème de la source** (`SourceEcosystem` : `Packagist` → Composer, `npm` et `crates.io` → semver, Wordfence et Friends-Of-Presta → PHP), stocké avec chaque ligne d'`affected` (`scheme`) ; une plage `SEMVER` passe par semver quel que soit l'écosystème ; la version d'inventaire est analysée par le comparateur de la ligne | F0 : une plage Packagist sur `pkg:prestashop/module/<x>` ou `pkg:wordpress/plugin/<slug>` reste une plage Composer |
| **`last_known_affected_version_range`** (`< v` ou `<= v`, comparateur de la ligne) gardé ; il ne réduit pas le verdict : au-delà, sans `fixed`, `Affected` avec `beyond_last_known` ; illisible : ignoré et compté | Une plage ouverte d'OSV signifie « toutes les versions suivantes » ; la borne n'est qu'une information pour F7 |
| **Gravité** : un score retenu, en **dixièmes entiers** (`Score { tenths: u8 }`, 0 à 100 ; jamais de flottant hors de `cvss.rs`), avec son origine (`wordfence`, `friends_of_presta`, `cvss_v31`, `ghsa_severity`), par l'ordre F0 ; `provided_score` (F3) borné à [0, 10] ; CVSS v3.0 et v3.1 calculés par la formule 3.1 (`Roundup` entier de l'annexe A) ; vecteur v4 validé et gardé, **jamais calculé** ; `informational` (Wordfence) et `malicious` (`MAL-` en id ou alias) en booléens | Décisions F0 ; un seul calculateur, v3.1, court et vérifiable par les exemples de la spécification |
| **Licence et attribution par enregistrement** : `licence_for_id(prefix)` (`GHSA`, `EEF` → `CC-BY-4.0` ; `DRUPAL` → `MIT` ; `MAL` → `Apache-2.0` ; `RUSTSEC` → `CC0-1.0`), table fermée testée ; préfixe inconnu dans un dump OSV : faille **gardée** avec la licence « inconnue » et l'attribution de la source (OSV.dev, lien vers l'enregistrement), comptée `unknown_license` et signalée par `vigie vulns sources` (une faille écartée serait un faux négatif silencieux) ; `attribution` assainie et bornée (2 000 caractères), remplie par F3 avec `copyrights` de Wordfence (message, notices, licences, liens, MITRE) ; `show` imprime licence et attribution | F0 : chaque mention conservée avec l'enregistrement et reproduite partout où la faille est affichée ; une faille connue ne disparaît jamais du rapprochement pour une raison administrative ; la licence inconnue est visible et à résoudre |
| **Constructeur validé** `Advisory::build(Draft)` : `from_osv` et les convertisseurs de F3 (Wordfence, Friends-Of-Presta) passent par la même validation et les mêmes bornes. `published` facultatif, `modified` obligatoire. Wordfence `from_inclusive: false` : le modèle n'a pas de borne basse exclusive ; F3 la traduit par `introduced` = la borne (inclusive, signalement de trop plutôt qu'en moins), limite écrite dans `failles.md` | Une seule porte d'entrée vers la base ; la prudence de F0 (« un signalement de trop qu'une faille tue ») |
| **Texte** : `summary` = `LogText::new(brut, 500)` ; à défaut, première ligne de `details` assainie et bornée (728 DRUPAL sans `summary`) ; `details` jamais stocké ; alias normalisés (`cve-` → `CVE-`, préfixes connus en majuscules) | Une règle d'assainissement pour tout texte servi ; jonction par CVE fiable (F4, F7) |
| **Références** : `ADVISORY`, `FIX`, `WEB` ; `http`/`https` sans `user:pass@`, 2 048 caractères au plus ; 10 gardées (`ADVISORY`, `FIX`, `WEB`, puis ordre de la source) | Une référence refusée (`javascript:`) est retirée seule ; la faille reste détectable |
| **purl : module unique** `vulns/purl.rs`, grammaire commune de `failles.md` ; `purl.json` au **format JSON simple** (`[{"in": "<purl>", "out": "<purl canonique>" | null, "why": "…"}]`), rejoué par le test PHP de l'agent (F5) ; la traduction OSV → purl a ses propres vecteurs (`osv-purl.json`, Rust seul) ; `from_osv` rend **un ou deux** purl (`prestashop/<x>`) et chaque purl donne une ligne `vuln_affected` | F0 : une grammaire, un module, des vecteurs partagés ; un composant émis n'est jamais écarté en silence à la réception |
| **Stockage par générations, réservées et sous bail** : `vuln_sources.next_generation` monotone, réservée en transaction IMMEDIATE et **jamais réutilisée** ; bail `loading_generation` + `loading_since` : un second chargement est refusé tant que le bail court (6 h), le reprend après expiration ; écriture par lots de `VULN_BATCH` failles (IMMEDIATE chacun, **bail revérifié dans chaque lot** : expiré ou supplanté → abandon immédiat) ; bascule en **compare-and-swap** (`active_generation` attendue et bail toujours détenu, sinon échec et génération orpheline) ; purge par lots de tout sauf l'active et celle sous bail en cours ; `PRAGMA wal_checkpoint(PASSIVE)` après la bascule et la purge | Remplacement atomique sans tenir le verrou pendant un dump npm (≈ 230 000 entrées) ; deux synchronisations concurrentes (timer et main) ne peuvent ni se mélanger ni écraser une génération plus récente ; le WAL ne grossit pas indéfiniment |
| **Index** : enfants `vuln_aliases` et `vuln_affected` indexés par `(source, generation, advisory_id)` (jointure et purge) ; `vuln_affected(purl_type, purl_namespace, purl_name, source, generation)` (rapprochement) ; `vuln_aliases(alias)` ; purge par `DELETE … WHERE rowid IN (SELECT rowid … LIMIT n)` | Purges et lectures bornées, sans balayage de table |
| **Corrections de plage hors des générations** : la table de correction (Friends-Of-Presta, F3) est clé `(source, advisory_id, purl)`, jamais rattachée à une génération ; F1 n'en crée pas mais garde le modèle compatible | Une resynchronisation ne doit pas effacer une correction auditée |
| **Migration 0015** (dernière : 0014) ; à l'implémentation, **prendre le prochain numéro libre**, ajuster `SCHEMA_VULNS`, et mettre à jour les tests existants de `store.rs` qui figent la version (`assert_eq!(…, SCHEMA_REGISTRY)` → `MIGRATIONS.len()` là où c'est la dernière) et l'instantané `migration_files_build_the_expected_schema` | Une migration publiée ne se modifie jamais ; les tests d'instantané doivent refléter le nouveau schéma |
| **Écrivain** : seule la synchronisation (F2, processus lancé par un timer) écrit ces tables, par `Store::open` ; `serve` les lit seulement (F7) | Même modèle que l'analyse de logs |
| **CLI de lecture seule** (`Store::open_read`) : `sources`, `show <id|alias>`, `match <purl>` ; base absente ou antérieure : « aucune base de failles » ; `match` sans version : toutes les failles du paquet en « version inconnue ». Erreur d'usage typée (`UsageError`, purl ou id mal formé) → code 2, comme `ConfigError` | Périmètre de l'issue ; codes de sortie cohérents avec le reste de la CLI |
| **Fixtures** : vrais enregistrements **OSV/GHSA seulement** (GHSA Composer, GHSA npm, RUSTSEC), intacts, avec `tests/fixtures/vulns/osv/NOTICE` (par fichier : source, licence, lien, modifications ; mention « données publiques de tiers », références minimales gardées par l'enregistrement lui-même) ; Wordfence et Friends-Of-Presta **fictifs** ; `tests/fixtures/versions/NOTICE` avec le **texte MIT complet** de `composer/semver`, son lien et la liste des vecteurs repris | F0 ; dépôt public = redistribution |
| **Test différentiel PHP** : `tests/vulns_php_diff.rs`, `#[ignore]`, **échoue au lieu d'être sauté** quand `VIGIE_PHP` est posé ; même forme que `VIGIE_E2E_PHP` (préfixe de commande `docker run … -v /tmp:/tmp … php`), paires écrites dans un fichier sous `/tmp` ; pas CI Linux avec la même image épinglée. Couvre `version_compare` (WordPress, PrestaShop) et la comparaison Composer sur formes normalisées ; la normalisation est couverte par les vecteurs repris de `composer/semver` | La CI a déjà PHP 8.1 ; Composer n'est pas dans l'image ; aucun poste n'est bloqué sans PHP |
