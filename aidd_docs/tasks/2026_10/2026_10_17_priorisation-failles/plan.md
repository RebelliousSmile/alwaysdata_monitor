| Élément | Valeur |
| --- | --- |

| Réponse | `200`, `content-type: text/plain; charset=utf-8`, `cache-control: max-age=300`, **pas de `Last-Modified`** [V] |
| ETag | fort, 64 caractères hexadécimaux entre guillemets ; `If-None-Match` → **304** [V] |

| Licence | CC0 (README de `cisagov/kev-data`, « *identical to the licensing found at* » `cisa.gov/…/kev/license.txt`) [V] ; ni logo CISA ni sceau DHS |

EPSS n'est pas joignable d'ici : URL, redirection, en-têtes, poids et conditions restent à relever depuis le VPS (`failles.md`, « À vérifier », point 3). Format rapporté [S] : première ligne `#model_version:…,score_date:…`, puis `cve,epss,percentile`, ≈ 300 000 à 383 000 lignes.

### Interface attendue du cadre F2 (à confronter au plan F2 dès qu'il existe)

Le plan F2 n'existe pas encore. F4 suppose, et la phase 3 adapte à ce que F2 aura réellement livré, sans dupliquer :

- un registre de sources parcouru par `vigie vulns sync [--source <id>]`, lancé par le timer quotidien ;
- un téléchargeur borné (`Download`) : HTTPS seulement, hôtes codés en dur par source (redirections limitées à ces hôtes), `If-None-Match` / `If-Modified-Since`, plafonds de taille compressée, décompressée et de durée, dossier de travail 0700 nettoyé, empreinte SHA-256 (empreinte inchangée → aucune écriture), et un point d'injection de tests (serveur HTTP local) ;
- l'état par source dans `vuln_sources` (F1, plus ce que F2 y ajoute : ETag, `Last-Modified`), un 304 valant succès ;
- le constat d'avertissement `vulns-sync/<source>` au-delà de 3 jours sans succès, résolu au succès suivant ;
- l'interdiction de tout autre hôte que ceux de `failles.md`.

Si F2 a déjà promu `flate2` en dépendance (zip OSV, tar.gz), la phase 3 n'y touche pas.

## Decisions

| Decision | Why |
| -------- | --- |
| **La règle de F0 fait foi, pas le tableau de l'issue #18.** Écart écrit dans `decisions.md` : l'issue proposait « CVSS ≥ 9 et correctif disponible → avertissement » et ne nommait ni `MAL-` ni la gravité inconnue ; F0 (postérieure) a tranché : KEV, `MAL-` ou CVSS ≥ 9,0 → critique ; CVSS ≥ 7,0, EPSS ≥ 0,1 ou gravité inconnue → avertissement ; « aucun correctif » ne fait jamais baisser la gravité | `decisions.md` est la référence des failles ; un CVSS 9,8 sans correctif reste critique |
| **Un seul module `vigie/src/vulns/severity.rs`, fonction pure** `assess(&AdvisoryFacts, &impl Exploitation) -> Assessment`. `AdvisoryFacts` : CVE de la faille (identifiant s'il est un CVE, plus ses alias CVE normalisés par F1), `malicious`, `score: Option<Score>` (valeur et origine, déjà choisie par `Score::select` de F1), `informational`, `fix_available`. `Assessment` : `severity` (`finding::Severity`), `rule` (règle qui a tranché), fait KEV retenu, fait EPSS retenu, score, `no_fix`. Aucune lecture de base, d'horloge ni de configuration dans le module | F7 (#21) appelle cette fonction pour chaque faille d'un constat ; une fonction pure se teste par table et ne dépend ni du stockage ni du réseau |
| **Règles lues de haut en bas, la première qui s'applique tranche** : (1) un CVE dans KEV → critique `Kev` ; (2) `malicious` → critique `Malicious` ; (3) score ≥ 9,0 → critique `CvssCritical` ; (4) score ≥ 7,0 → avertissement `CvssHigh` ; (5) EPSS ≥ 0,1 → avertissement `Epss` ; (6) aucun score et non `informational` → avertissement `UnknownSeverity` ; (7) aucun score et `informational` → information `Informational` ; (8) sinon information `Default`. `fix_available` n'entre dans aucune règle | Transcription littérale de F0 ; `informational` ne déclasse qu'une faille qu'aucune règle critique ou d'avertissement ne retient ; la règle nommée sert à l'affichage (« critique : exploitée, CISA KEV ») |
| **Règle des inconnues séparée** : `assess_unknown(reason, component_max: Option<Severity>) -> Severity` ; `VersionUnknown` → avertissement si l'une des failles du paquet (toutes, la version étant inconnue) est critique par `assess`, sinon information ; `RangeUnknown` → avertissement si la faille dont la plage est inconnue est critique par `assess` (KEV, `MAL-`, CVSS ≥ 9,0), sinon information | F0 (révisé le 2026-10-17) : « version inconnue » ou « plage inconnue » sur une faille critique → avertissement ; information sinon |
| **Seuils exacts, sans flottant** : score comparé en dixièmes (`Score::tenths()`, arrondi au dixième le plus proche ; si F1 stocke déjà des dixièmes, tel quel) aux constantes `CVSS_CRITICAL_TENTHS = 90` et `CVSS_WARNING_TENTHS = 70` ; EPSS stocké et comparé en millionièmes entiers (`EPSS_WARNING_PPM = 100_000`), le texte décimal du CSV étant converti **par troncature** sans passer par `f64` | Les bornes 7,0, 9,0 et 0,1 sont exactes ; la troncature ne fait jamais franchir 0,1 dans un sens ou dans l'autre ; aucun écart de représentation binaire |
| **Seuils en constantes, pas en configuration** | F0 les a fixés ; changer un seuil est une décision écrite dans `decisions.md`, pas un réglage par VPS. « Paramétrée par les seuils de F0 » (issue) = constantes nommées en tête du module |
| **Plusieurs CVE** : KEV si l'un des CVE y est (fait retenu : `dateAdded` le plus ancien, `ransomware` si l'un l'est) ; EPSS = le plus haut score parmi les CVE (et son percentile) ; faille sans CVE : ni KEV ni EPSS, gravité par `malicious` et score seuls | Une faille exploitée sous l'un de ses identifiants l'est tout court ; l'issue : « une faille sans CVE n'a ni KEV ni EPSS » |
| **Type `Cve` validé** : grammaire du schéma KEV `CVE-[0-9]{4}-[0-9]{4,19}`, préfixe en majuscules (F1 normalise déjà `cve-`) ; alias non conforme ignoré pour la jointure | La jointure KEV/EPSS ne doit jamais rater un CVE pour une question de casse, ni accepter n'importe quel texte |
| **Trait de lecture `Exploitation`** (`kev(&Cve) -> Option<KevFact>`, `epss(&Cve) -> Option<EpssFact>`, `state() -> TablesState`) avec deux implémentations : `MemoryTables` (tests, construite depuis des lignes) et `StoreTables` (phase 2) | F7 et les tests de F4 utilisent la même règle avec des tables différentes ; la règle ne connaît pas SQLite |
| **`TablesState`** : pour KEV et EPSS, chargée (version et date du jeu) ou jamais chargée ; porté par `Assessment` pour l'affichage (« KEV non chargé ») ; une table absente ne lève aucune gravité | Une table manquante ne doit pas passer pour « non exploitée » en silence ; le constat `vulns-sync/<source>` de F2 rend l'absence visible |
| **Propriétés vérifiées en plus de la table** sur une grille exhaustive (KEV × `malicious` × score sur les bornes × EPSS sur les bornes × `informational` × `fix_available`) : ajouter KEV, `malicious`, un score plus haut ou un EPSS plus haut ne fait jamais baisser la gravité ; `fix_available` ne la change jamais ; `informational` ne la fait jamais monter | Les invariants de F0 sont prouvés pour toutes les combinaisons, pas seulement pour les lignes choisies |
| **KEV et EPSS ne passent pas par `VulnSource`** : trait voisin `EnrichmentSource` dans le même cadre (même registre, même `Download`, même état `vuln_sources`, même constat `vulns-sync/<source>`, même `--source`), dont `load` pousse des lignes typées dans un puits (`EnrichSink`) au lieu de rendre des `Advisory` | `VulnSource` rend des failles validées par `Advisory::build` et rangées dans `vuln_advisories` ; une ligne KEV ou EPSS n'en est pas une. EPSS (≈ 300 000 lignes) doit aller en flux vers la base, pas dans un `Vec` |
| **Stockage par générations, comme F1** : `vuln_kev` et `vuln_epss` portent une colonne `generation` ; les sources `kev` et `epss` ont leur ligne dans `vuln_sources` (`active_generation`, `next_generation`, bail `loading_generation` / `loading_since`) ; chargement par lots IMMEDIATE de `ENRICH_BATCH` lignes (bail revérifié à chaque lot), bascule en compare-and-swap, purge par lots de tout sauf l'active et celle sous bail, `PRAGMA wal_checkpoint(PASSIVE)` après | Remplacement atomique sans tenir le verrou d'écriture pendant 300 000 insertions : `serve` (écrivain unique) et `tick` écrivent entre deux lots ; un lecteur voit l'ancien jeu complet ou le nouveau, jamais un mélange ; mêmes garanties et mêmes tests que F1 |
| **Primitives de génération partagées** : F4 réutilise celles de `vulns/store.rs` (F1). Si F1 les a gardées propres aux failles, la phase 2 les extrait dans `vulns/generation.rs` (réserver, revérifier le bail, compare-and-swap, purger par lots une liste de tables) **sans changer leur comportement**, tests de F1 inchangés et verts | Un seul code de bail et de bascule ; pas de second mécanisme à prouver |
| **Rejeté : table fantôme puis `ALTER TABLE … RENAME`** | Le DDL invalide les requêtes préparées des autres connexions (`serve`) et tient le verrou de schéma ; les générations sont déjà écrites et prouvées par F1 |
| **Rejeté : `DELETE` puis 300 000 `INSERT` dans une transaction** | Verrou d'écriture tenu plusieurs secondes : au-delà du `busy_timeout` de 5 s, les écritures de `serve` et `tick` échoueraient |
| **`vuln_epss` en `WITHOUT ROWID`, clé `(generation, cve)`** ; `vuln_kev` aussi | La clé primaire est l'index de lecture : pas de second index (≈ moitié de place pour 300 000 lignes, deux générations coexistant pendant un chargement) ; la purge par lots passe par la clé (`cve IN (SELECT cve … WHERE generation = ? LIMIT n)`) |
| **Métadonnées du jeu par génération** dans `vuln_dataset (source, generation, version, released, rows)` : KEV `catalogVersion` et `dateReleased` ; EPSS `model_version` et `score_date` ; lues jointes sur `active_generation` | Basculées avec les lignes dans la même transaction de commit ; l'écart à l'issue (`model_date` par ligne) évite 300 000 copies de la même date |
| **Champs KEV retenus** (liste de l'issue) : `cveID`, `dateAdded`, `dueDate`, `knownRansomwareCampaignUse` (`Known` → vrai, `Unknown` → faux, autre → inconnu, compté), `vulnerabilityName` (`LogText`, 200 caractères). `shortDescription`, `requiredAction`, `notes`, `cwes`, `forensicTriage` lus comme `IgnoredAny` | Seuls ces champs servent à la priorisation et à l'affichage ; moins de texte tiers stocké |
| **Analyse KEV stricte et bornée** : document de 16 Mio au plus (1,8 Mio mesuré), 20 000 entrées au plus (1 748), `serde_json` depuis le fichier téléchargé (champs inconnus ignorés) ; en-tête requis ; entrée à `cveID` hors grammaire, à date illisible ou en double (la seconde) écartée et comptée ; `count` différent du nombre d'entrées compté `count_mismatch`, sans échec | Le schéma publié est la référence ; une entrée cassée n'empêche pas les autres ; un JSON tronqué échoue déjà à l'analyse |
| **Analyse EPSS en flux** : `flate2::read::MultiGzDecoder` sur le fichier téléchargé, lecture ligne par ligne (`read_until` borné à 128 octets par ligne), décompressé plafonné (64 Mio) ; première ligne `#model_version:<v>,score_date:<RFC 3339>` exigée ; en-tête exactement `cve,epss,percentile` ; ligne : `Cve`, puis deux décimaux dans `[0, 1]` (au plus 9 décimales) ; 2 000 000 lignes au plus ; ligne invalide écartée et comptée | Le CSV entier n'est jamais en mémoire ; une bombe gzip ou une ligne sans fin s'arrête au plafond ; un format changé (commentaire ou en-tête) échoue au lieu de charger n'importe quoi |
| **Seuil de rejet** : plus de 1 % de lignes ou d'entrées écartées → synchronisation de la source en échec, génération active conservée | Au-delà, c'est le format qui a changé, pas une ligne isolée |
| **Garde contre le rétrécissement** : un nouveau jeu de moins de 90 % des lignes de l'actif (KEV) ou de 80 % (EPSS) est refusé, source en échec, ancien jeu gardé ; `vigie vulns sync --source kev|epss --accept-shrink` l'accepte une fois, inscrit au journal | KEV ne fait qu'augmenter la gravité : un catalogue tronqué ou altéré la ferait baisser en silence. Un retrait légitime reste possible, par un geste explicite de l'exploitant |
| **KEV : miroir d'abord, cisa.gov en secours** : URL du miroir `raw.githubusercontent.com/cisagov/kev-data/main/known_exploited_vulnerabilities.json`, puis `www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json` si le miroir échoue (réseau, HTTP autre que 200 ou 304, plafond, analyse) ; ETag gardé avec l'URL qui l'a servi, requête inconditionnelle quand l'URL change ; empreinte SHA-256 commune : même contenu par l'autre hôte → aucune écriture | Le miroir est joignable du conteneur et sert ETag et 304 [V] ; cisa.gov est la source canonique, joignable du VPS seulement [NV]. Les ETag de deux hôtes ne se comparent pas ; l'empreinte, si |
| **EPSS** : `https://epss.empiricalsecurity.com/epss_scores-current.csv.gz`, redirection suivie seulement vers `epss.cyentia.com` ou `epss.empiricalsecurity.com` (3 sauts au plus) ; requête conditionnelle si le VPS montre ETag ou `Last-Modified`, sinon l'empreinte évite la réécriture | Liste d'hôtes de `failles.md` ; l'API `api.first.org` n'est jamais appelée (elle dirait quels CVE touchent les sites) |
| **Plafonds provisoires, à confirmer par le relevé du VPS** : KEV 16 Mio ; EPSS 32 Mio compressé, 64 Mio décompressé, 2 000 000 lignes ; durée selon F2. Relevé masqué (taille, ETag, durée) consigné dans `hebergement.md` | Le poids d'EPSS n'est pas mesuré [NV] ; les plafonds laissent un facteur ≥ 4 sur l'estimation (≈ 383 000 lignes × ≈ 30 o) |
| **`flate2` passe en dépendance** (déjà au `Cargo.lock`, `rust_backend` en Rust pur, sans nouvelle crate), sauf si F2 l'a déjà fait | Seule façon de lire le `.csv.gz` ; compatible musl et `check-tls-deps.sh` |
| **Lecture pour F7 : `StoreTables`** : KEV entier chargé en mémoire à l'ouverture (≤ 20 000 lignes, une transaction de lecture) ; EPSS lu par clé `WHERE generation = (SELECT active_generation … 'epss') AND cve = ?`, une instruction par CVE, mise en cache le temps d'un passage | Chaque lecture voit une génération active entière ; la purge n'enlève jamais l'active. KEV est petit, EPSS ne tient pas utilement en mémoire de `serve` |
| **Montée de gravité sans changement d'inventaire** : F4 garantit qu'après un chargement, `assess` sur les mêmes faits rend la nouvelle gravité (test sur deux générations) ; la mise à jour du constat F7 ouvert au passage suivant est un critère transmis à F7 (#21), qui seul possède les constats | Le critère d'acceptation de l'issue porte sur un constat F7 qui n'existe pas encore ; F4 en prouve la moitié qui lui revient |
| **Attribution et licence** : `vuln_sources` des deux sources : KEV `CC0-1.0`, attribution « CISA KEV » (aucune exigée, aucun logo) ; EPSS licence « FIRST EPSS Usage Agreement », attribution « See EPSS at https://www.first.org/epss », imprimées par `vigie vulns sources` et `show` | F0 ; F7 les reprend dans l'API et la console |
| **CLI** : `vigie vulns sources` montre `kev` et `epss` (version et date du jeu, lignes, écartées par raison, âge, attribution) ; `vigie vulns show <id|CVE>` ajoute, par CVE, KEV (`dateAdded`, échéance, rançongiciel) et EPSS (score, percentile, date du modèle), puis la gravité F0 et la règle qui l'a fixée | Vérifier à la main pourquoi une faille est critique, sans attendre F7 |
| **Fixtures fictives** pour KEV et EPSS, de même structure que les vraies (champs mesurés le 2026-10-17), CVE inventés (`CVE-2026-9xxxx`), aucun enregistrement réel | Pas de `NOTICE` à tenir ; les CVE fictifs s'alignent sur les failles fictives de F1 |
